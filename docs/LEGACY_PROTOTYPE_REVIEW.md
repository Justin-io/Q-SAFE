# Legacy prototype review and migration notes

This branch replaces the original proof-of-concept implementation with a separate, non-executing scanner. The previous files remain reachable in Git history on main; they have been removed from the active tree because several were misleading, destructive, unsafe to run, or unrelated to defensive file inspection.

## File-by-file review of the original tree

| Original path | Review |
|---|---|
| .gitignore | Mostly conventional Python ignores; updated to exclude runtime logs and reports. |
| Makefile | Built the research control-flow monitor and deliberately compiled an unsafe demo with stack protection disabled and an executable stack. Replaced with test, scan and monitor targets only. |
| README.md | Described the program as “Real Mode” and kernel-like despite being a user-space Linux program. Claimed register checks established integrity and advertised permanent file deletion. Rewritten to describe actual capabilities and limits. |
| agent_triage.py | Classified paths by folder names such as Desktop/tmp/Downloads rather than file behaviour. Invoked curl through a shell command and used a cloud LLM as a path triage authority. Not suitable as a security decision engine. |
| allowlist.bin | 24-byte demo binary containing a count and two 64-bit rolling-context values. Not a signed or protected trust database. Removed as a generated artifact. |
| attack.txt | Prompt-injection-like text instructing deletion of logs. It is a toy test string, not a malware sample. |
| dashboard.py | Displayed random industrial telemetry, fabricated IP events, random risk progress and a size-only SAFE verdict. It was not connected to a real scanner. Replaced with a UI that reports live Q-SAFE scan output. |
| deep_core.o | Small ELF object built from the assembly payload simulation. Static inspection showed a symbol named deep_core_payload; it is not a kernel module. Removed binary build output. |
| exploit_gen.py | Generated a buffer-overflow/return-address overwrite file for the intentionally vulnerable demo. Not part of a defensive scanner; removed from the active branch. |
| folder_list.txt | Static list of system directories. It was not a trustworthy inventory of current suspicious files. Removed as generated/static test data. |
| guardian.asm | User-space x86-64 assembly launcher, not real mode or kernel protection. It ran broad filesystem discovery, invoked commands through system(), built a shell command with a file path, read content into a fixed buffer, and directly called unlink after a weak signature/LLM verdict. Removed from the active scanner path. |
| innocent_script.py | Harmless Hello World test script generated by the old launcher. |
| kernel_hook.asm | Payload simulation with a syscall and marker bytes. It is not a Linux kernel hook or loadable kernel module. Removed from the active tree. |
| llm_response.txt | Empty output placeholder from the old cloud scan flow. |
| neural_oracle.py | Did not derive a control-flow graph from source. It hard-coded expected function IDs and generated an allowlist for a different sample application. This did not validate the driver's actual control flow. |
| payload.elf | Despite the extension, its contents were plain text beginning with a fake ELF header; it was not a valid ELF executable. |
| protected_app | Prebuilt ELF for the deliberately vulnerable sample application. Not executed during this review; removed as a checked-in binary artifact. |
| protected_app.c | Deliberately read up to 512 bytes into a 64-byte stack buffer. The Makefile disabled stack protections and enabled an executable stack for the demo. This is intentionally vulnerable research code, not a defensive component. |
| qsafe_demo | Prebuilt demo executable for the control-flow-hashing experiment. Not executed; removed as a checked-in binary artifact. |
| qsafe_driver.c | Simulated function-call sequence monitoring. Its function IDs differ from the hard-coded IDs in the neural oracle, so the normal demo flow was not consistently represented by the generated allowlist. |
| qsafe_driver.o | Compiled object file; build output, not source. |
| qsafe_monitor.asm | Rolling shift/XOR hash allowlist check. This is not a general control-flow-integrity mechanism: state is global, does not model call/return nesting, and has no protected allowlist provenance. |
| qsafe_monitor.o | Compiled object file; build output, not source. |
| rootkit_installer.sh | Printed an installation message and then ran rm -rf /var/log. It was destructive and did not install a rootkit or legitimate defensive agent. Removed. |
| run.sh | Rebuilt and ran the unsafe assembly scanner, deleted generated files, and rewrote sample artefacts including the destructive rootkit-named script. Replaced with a minimal launcher for qsafe.py. |
| start_ui.sh | Assumed a local virtualenv and launched Streamlit; no dependency check or scanner integration. Replaced by documented optional dashboard startup. |
| sus_folders.txt | Empty output placeholder from folder triage. |
| target_scan_list.txt | Empty output placeholder from deep-scan target handoff. |
| triage_req.json | Saved request containing a large directory list and prompt for LLM folder selection. Not a trusted ruleset or model. |

## Migration decision

The original control-flow hashing experiment is not silently presented as a production defence. Its vulnerable app, payload stubs, exploit generator, destructive shell script, assembly scanner and prebuilt objects have been removed from this branch's active project tree. Git history preserves the original proof of concept for audit. Q-SAFE now has one safe-by-default scanning entry point, explicit optional analysis engines, file-integrity baselines and reversible quarantine.
